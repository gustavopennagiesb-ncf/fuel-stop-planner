# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Use the project venv (`.venv`, Python 3.12, Streamlit installed); the system `python` does not exist and system `python3` has no pytest. `AppTest` works against `app.py` (see `tests/test_driver_tab.py`); patch `providers.fueleconomy._get` so the sidebar car lookup never hits the network.

```bash
.venv/bin/python -m pytest -q                       # all tests (no network, no keys)
.venv/bin/python -m pytest tests/test_google_mode.py::test_detours_are_memoized_across_reruns -q   # one test
streamlit run app.py                                # fixture mode (default, synthetic data)
PROVIDER=google streamlit run app.py                # real data; app.py loads .env via envfile.py (shell vars win)
.venv/bin/python scripts/day1_check.py              # live API sanity check (1 Places + 1 Routes call, billed)
```

No linter or build step is configured. Run pytest before every commit; keep commits small.

## Architecture

Streamlit app (`app.py`, 5 pages chosen in the sidebar: Where to stop, When to fill up, Sensitivity, EDA, How to use; the AI assistant floats on every page) over a thin service layer. Flow: `config.py` (env flags) → `services.py` (switches on `PROVIDER`) → `providers/*` (HTTP + parsing, no UI) → pure-math modules (`geo.py`, `detour.py`, `forecast.py`, `driver.py`, `fuelplan.py`) → `app.py`.

- **Provider switch**: `fixture` (default, synthetic, needs no keys) or `google`. `services.load_trip` / `load_series` silently degrade to fixtures when keys are missing, and `app.py` falls back to a fixture trip on any exception. Always pass `provider=` explicitly in tests instead of relying on `config.PROVIDER`.
- **"Where" pipeline (google)**: Routes direct route → polyline decoded in `geo.py` → Places `searchNearby` around points sampled every 25 km (capped by `MAX_PLACES_CALLS`) → `corridor_filter` → `services.compute_detours` measures up to `MAX_ROUTE_CALLS` stations with Routes on a local 10 km stretch around each (`_local_detour`: base leg and `via` leg, traffic-unaware; never a whole-trip `via`, which makes Google pick another road), always the best-ranked unmeasured one by the app's `priority` (estimated net benefit), re-ranking after each; the station closest to the route is measured first and the smallest raw detour is subtracted (every stop leaves the road). Memoized 10 min in `_detour_memo` (so Streamlit reruns on slider moves do not bill again). Unpriced/failed stations keep the out-and-back estimate in `detour.rank_stations`; the `detour_source` field marks which one was used.
- **Car lookup**: `providers/fueleconomy.py` feeds the "Look up my car" expander under "Your car" (main area). Picking a car (or switching city/combined/highway) writes `st.session_state["mpg"]` once per `(car id, kind)`, tracked in `mpg_applied`, so the mpg slider (`key="mpg"`) stays hand-editable. Menus are cached 24 h; if the API is down (5 s timeout, or an unusable response, both `requests.RequestException`) the slider still works and the lookup is not retried for 60 s (`fe_down_until` in session state), so reruns never wait on it. Plug-in hybrids get a warning because their EPA figures blend electricity. In `AppTest`, address widgets by `key=`; the EPA figure and the reserve are segmented controls, so use `at.button_group(key=...)`.
- **Net benefit** (`detour.py`): `G*(p_ref - p_station) - extra_miles/mpg*p_station - vot*extra_min/60`; `p_ref` is the median price of stations within 800 m of the route, or a user-typed price. Users can edit any station price in the UI, and typed prices always work.
- **"When" pipeline**: EIA weekly Florida/U.S. retail series plus WTI crude (`PET.RWTC.W` via the v2 `seriesid` endpoint, $/bbl, Friday aligned to the following Monday; `providers/eia.fetch_wti`, joined in `load_live` as column `wti`; if the crude fetch fails the retail series still loads) cached to `data/eia_weekly.csv` and reused if the API is down. `forecast.py`: `crude_model` (OLS per horizon on [1, Δpump(t), Δcrude(t), Δcrude(t−1)], refit on an expanding window, evaluated with `rolling_origin_eval`), `crude_signal` (verdict wait / fill / none at `SIGNAL_THRESHOLD` = 0.03 $/gal, an assumption; EIA updates crude on Wednesdays and retail on Mondays, so when this week's crude is missing it shifts crude one week and returns `crude_lag_weeks: 1`; `signal_and_record` then replays the track record and period ratios on the same shifted crude, so a lighter forecast never wears the full model's record), `signal_track_record`, `monthly_change_profile`, `signal_text`. The page shows a verdict card (`key="answer_when"`) with the expected change, the track record, and charts of price, crude→pump correlation by lag and average change by month; without crude data it falls back to the old answer card. The honest result stays modest: the crude model beats naive by a small margin that has shrunk in recent years, and the simple methods (drift, 4-week average, same week last year) do not beat naive. Synthetic mode has a synthetic crude that leads the synthetic U.S. price.
- **Reserve** (`driver.py`): `reserve_gallons` (15% of the tank, at least 2 gal; an assumption documented in the module docstring) is what the fuel plan keeps in the tank. The Driver tab was removed; the rest of `driver.py` (range bands, hours, orders) is no longer shown in the UI.
- **Fuel plan** (`fuelplan.py`, pure): with a fuel level set in the "Fuel now" chip (popover "How much fuel do you have?": `fuel_input_mode` Fuel gauge | Miles left, `fuel_level_eighths`, `fuel_miles_left`; none selected = not set), `fuelplan.plan` always runs: it decides `stop_needed` (reserve = `driver.reserve_gallons(tank, "standard")`), drops unreachable stations before ranking (never rank them with 0 gal), gives the arrival fuel and the tank-size caption, and gives each station its own gallons, passed to `rank_stations` / `flip_point` as a `{id: gallons}` mapping (`gallons_arg`). `recommend(..., stop_needed=)` adds the `no_stop` verdict; a skip with a stop needed is titled "Stop for fuel" and names the reachable station reached first along the route (`summary(rec, nearest=)`). "Set gallons by hand" (`gallons_manual`) keeps the whole plan: only the gallons change, to the slider's one number for every station, and the app stops writing the slider. Under a plan (not by hand), `gallons_used = ranked[0]["gallons"]` for every verdict; the slider only when nothing ranks or by hand. `gallons_used` is the one figure Sensitivity, the flip-point sentence and `assistant_facts` (`gallons`) read. The sidebar gallons slider is drawn into a reserved `fill_slot` after the shared computation, so the app can write its choice (clamped 3-25, exact value in a caption) into `st.session_state["gallons"]` before drawing it. `llm.template_explanation` follows the verdict (no_stop, skip, go). Fuel level not set: today's path (`fplan = None`).
- **LLM layer** (`llm.py`): the model only phrases numbers that the code computed; `validate()` checks every number in the output against the `facts` dict, retries, then falls back to a deterministic template. A configured provider that fails returns `error` (bad key, no credits, network) and the app shows it, so a rejected key never looks like "no key given". Facts must be pre-rounded to the precision the text uses. Works without `ANTHROPIC_API_KEY` (template only).

## Constraints that shape changes

- Google Places content must not be stored (only place IDs) and must be shown on a Google map: never commit recorded Google responses; fixtures stay synthetic. `gmap.py` renders the map via the Maps JS key (`GOOGLE_MAPS_JS_KEY`, a separate referrer-restricted browser key; the server key `GOOGLE_API_KEY` must never reach the page). Station names are untrusted: `gmap.py` escapes JSON for `<script>` and uses `textContent`.
- Places with `fuelOptions` and Routes `TRAFFIC_AWARE` are paid SKUs; keep call counts capped in `config.py`.
- Keys come only from env vars / `st.secrets`; `.env` is gitignored.
- The user's location (`location.py`, an `st.components.v2` button around `navigator.geolocation`) is sensitive: keep it in session state only, never log or store it, never render free text sent by the browser (errors arrive as numeric codes mapped to fixed messages), and in tests replace `location.request_location` instead of using a real browser.

- Empty start: the app opens with no route, no car and no fuel level. The route counts once "Find stations" is pressed (`trip_applied`; in fixture mode the same button loads the synthetic route), the car once it is looked up or its mpg slider is moved (`car_set`); until both are set (`_ready`), Where to stop shows a welcome checklist, Sensitivity and the assistant ask for them, and no paid search runs. "Start over" (`start_over`) clears them. `config.DEMO_TRIP` (env `FUEL_DEMO_TRIP=1`) starts from the demo trip instead; `tests/conftest.py` turns it on for every test, and `tests/test_empty_start.py` turns it off.
- Layout: the tabs open on the answer ("Where to stop") and end with the manual ("How to use"), each label carrying a Material icon; trip and car sit in one panel above the page (`trip_strip`), under a "Start here" hint: the choices on the left (`trip_choices`, three full-width popovers) and a summary grid of `fs-chip` cards on the right, edited in the "Where are you going?" and "Pick your car" popovers (the google-mode `trip_form` and location button live in "Where are you going?"); "Where to stop" opens on a green answer card (`key="answer_go"`, title in `st.header`, four stat metrics) next to a route mini map; the AI assistant is a floating popover (`assistant_fab`) on every page; the sidebar holds navigation and the fill-up and time settings. The tab strip has `key="main_tabs"`, so a test opens a tab with `app.session_state["main_tabs"] = "<label with its :material/ icon>"` — without that, a guarded tab body never runs under `AppTest` (see `tests/test_tabs.py`). The `with tab_*` blocks stay in source order because "Where to stop" computes `p_ref`, `priced` and `ranked` that the EDA, Sensitivity and AI tabs read.
- Look: a dark theme lives in `.streamlit/config.toml`, with its own `[theme.sidebar]` palette, Geist / Space Grotesk fonts and thin borders; `tests/test_ui_style.py` reads those colors (main and sidebar) and enforces WCAG AA contrast, so change the palette there. The only injected CSS is `_SIDEBAR_CSS` in `app.py`: own `fs-*` classes (brand, section labels, title, chips, kicker) and `.st-key-*` selectors (nav buttons, `trip_choices`, `answer_go`, `assistant_fab`); never target `data-testid` or internal class names. The sidebar is divided into Navigate / Fill-up / Time / Data sections; mpg, tank and the trip stay in the main area (visible on a phone).
- Streamlit style rules followed (from the skill bundled with Streamlit in `.venv/.../.agents/skills`): theme in config.toml, `st.segmented_control` instead of horizontal radios (AppTest: `at.button_group(key=...)`), `alt=` on tables and charts, and `st.tabs(..., on_change="rerun")` with `is_open(tab)` so only the open tab's heavy body runs (widgets stay outside the guard so their values persist).
- **Where to stop**: answer first. `recommend.py` (pure) turns the ranked stations into go / skip / none, and also reports the cheapest price on the route (`cheapest`, which is not always the stop that saves most) (a stop must save at least `min_saving`, default $0.50, an assumption, and always more than $0); `maps_links.py` (pure) builds Google Maps URLs (pin and "navigate via this station": no API key, no cost; only coordinates, place ids and typed addresses go into a URL, never a station name). Station names are untrusted: `recommend.md_escape` before any Markdown. In synthetic mode the link buttons are off because the stations are made up. Origin, destination and corridor are in the "Your trip" card; in google mode they sit in a form (`trip_form`), so a paid search starts on "Find stations", not on every keystroke. In `AppTest`, put `set_value` and the submit click in the same run.
- **Price-is-a-bad-proxy panel** (`insight.py`, pure: no Streamlit, no network; built on `detour.rank_stations`): `regret`, `price_rank_gap`, `decision_grid` (re-ranks across `GALLONS_GRID` x `VOT_GRID`), `flip_point` and `corridor_vs_state`. Its figures must come from the same stations and the same settings as the recommendation (`regret` and `price_rank_gap` take the `ranked` list the headline uses; `decision_grid` and `flip_point` re-rank the same `detoured` stations at the current settings, and `flip_point` is exact because net benefit is linear in value of time), so the panel can never contradict it. "The cheapest won" is one definition (`cheapest net_benefit >= best net_benefit`, so a tie counts as a win) used by all three. The corridor-versus-Florida line shows only when the trip and the weekly series are both real or both synthetic.
- **Address suggestions** (`places_autocomplete.py`, an `st.components.v2` wrapper around Google's `PlaceAutocompleteElement`): runs in the browser with `GOOGLE_MAPS_JS_KEY`, which must allow the Places API (New); without the key, or if it fails, the trip card falls back to plain text boxes and says so. Everything the browser sends is untrusted (`parse_pick`: validated numbers, cleaned label, place id pattern, error codes mapped to fixed messages); picked labels are escaped before display. The trip is held as "pending" until "Find stations" (`trip_input.py`, `trip_applied` in session state), so typing, picking or using the location never starts a paid search. Load the Maps script with `callback=` (not `onload`) before calling `importLibrary`. In `AppTest`, replace `places_autocomplete.request_pick`.
